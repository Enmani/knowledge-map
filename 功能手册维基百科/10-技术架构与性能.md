# 技术架构与性能

[返回首页](./README.md)

本页同时记录当前架构和目标架构。标有“计划”或“目标”的内容尚未接入主应用。

## 总体结构

项目采用模块化前端结构。知识数据、图谱规则、布局计算、地图渲染、界面组件和玩家进度分别维护。早期版本使用本地内容文件和浏览器存储。服务端同步在账号和协作需求明确后接入。

主要模块如下：

```text
src/
  domain/          知识实体、关系、进度和校验
  content/         概念故事和来源
  engine/          场景、布局、LOD、相机和迷雾
  frontier/        前沿研究与奖项目录
  renderers/       地图渲染适配器
  features/        搜索、详情、进度和导航
  widgets/         互动组件及注册表
  persistence/     本地进度和设置
```

## 数据流

内容文件经过格式校验后进入知识图谱。场景投影器根据当前空间筛选节点和关系。布局引擎为主场景计算紧凑花瓣领域簇，为子场景计算依赖分列。LOD 管理器根据相机和屏幕尺寸生成可见层级。渲染器读取场景数据并更新地图。右侧卡片通过选中的概念 ID 读取内容。

知识数据不保存渲染器对象。布局坐标属于空间投影。玩家进度绑定概念 ID。地图渲染器可以替换，内容和进度保持兼容。

## 场景与 LOD

当前场景目录包含数学全景和 16 个子场景投影，其中 15 个直属数学全景，1 个直属微积分。多元微积分的规范投影与微积分中的别名投影各自关联向量微积分子场景。复动力系统在复分析和动力系统中使用共享概念投影。每个子场景通过稳定嵌入矩阵映射到所属父节点，递归组合后得到根坐标。单一根坐标相机负责全部缩放和平移。导航栈保存空间路径，换根只改变交互语义。界面挂载当前钻取关系的父层和子层。两个图层在进入和退出期间保持稳定，完全进入后父层透明度为零。

`src/features/map/analysisSceneContent.ts` 保存 10 组分析学专题节点数据。`sceneCatalog.ts` 将主地图节点、微积分节点、单节点专题和分析学专题统一转换为 `MapScene`。分析学专题场景使用 9200 × 3300 的世界区域、六倍卡片尺寸、220 个世界单位的节点间距和推进式布局。

LOD 使用节点投影到屏幕后的像素尺寸。连续显隐倍率会结合场景有效缩放和卡片尺寸倍率，使多层钻取保持接近的视觉触发尺寸。父作用域中的子层透明度由缩放进度和门户居中度共同计算；进入子作用域后只使用缩放进度。导航和交互作用域读取同一透明度值，在 80% 进入阈值和 20% 退出阈值之间保持滞回。单击子卡片可以将当前父子关系的显示值固定到 100%，缩放会解除固定，平移保留当前子域。子层完全显示时父层透明度归零。子节点选择只更新选择状态和详情，不修改相机矩阵。布局与父子嵌入矩阵在缩放过程中保持稳定。大型子场景的异步加载与缓存仍属于后续计划。

## 渲染边界

React 负责页面框架、搜索、右侧内容和互动组件。主画布使用 PixiJS v8 WebGL。渲染器在初始化时建立场景目录中的节点、连线、标签场、迷雾和文字图元，并在首帧前完成文字栅格化与纹理上传。运行帧更新相机矩阵、父子场景矩阵、透明度、可渲染状态和视觉权重。WebGL 初始化失败时，地图区域显示明确的错误状态。

布局算法、前置关系、解锁规则和内容数据不依赖 PixiJS。`MapRenderKernel` 把相机与作用域状态解析为稳定的渲染帧，PixiJS 适配器读取 `MapScene` 与交互状态。

## 性能策略

指针移动通过 `requestAnimationFrame` 合帧。相机矩阵保存在连续控制器中，动画帧交给 `MapRenderKernel` 计算场景合成结果，再由 PixiJS 更新保留图元的矩阵和透明度。React 状态在动画结束和作用域阈值事件中提交。缩放数字通过固定 DOM 文本节点读取连续相机矩阵并逐帧更新。

父层和子层分别保存稳定的选择、路径、筛选和 LOD 渲染上下文。作用域切换不会替换场景图层，也不会让节点和连线随当前空间重新生成。PixiJS 应用关闭连续 ticker，只在相机帧或视觉状态变化后提交一次显式绘制。

地图组件卸载或重新初始化时会取消尚未完成的 PixiJS 创建流程，并立即释放已建立的 Canvas、纹理与 WebGL 上下文。开发环境的严格模式重复挂载不会留下重叠画布或重复 GPU 资源。

每个标签场在场景建立时把成员圆和场域连接合并成一张裁剪后的低分辨率蒙版，再统一模糊、着色并上传为单个纹理。同一场域的几何重叠不会重复叠加透明度。场域之间使用普通透明度混合，在重叠位置形成混色。筛选只切换已存在纹理的可见性和整体透明度，平移和缩放不重建场域。当前帧最多显示一个父层和一个正在显现的子层。远处图元裁剪、子空间异步加载和构建期搜索索引属于后续计划。

缩放过程中更新世界变换和父子层透明度。子场景复用已经生成的布局、关系、文字与场域图元。WebGL 内部视口使用地图宿主元素的实际 CSS 宽高，命中坐标也从该边界换算；设备像素比只改变后备缓冲区分辨率。布局计算达到明显耗时时移入 Worker。

## 性能预算

当前 PixiJS 渲染器预构建场景目录中的图元。逻辑数据可以继续增长，常驻图元应控制在 3,000 个以内。桌面设备的连续平移和缩放目标为接近 60 FPS。点击反馈目标为 100 毫秒以内。暖缓存子空间展开目标为 100 毫秒以内。

性能数据需要在指定测试设备和浏览器中记录。官方库基准只能作为参考，不能替代项目场景测试。

## 故障处理

布局数据损坏时，场景回退到上一个 `layoutVersion`。子空间加载失败时，父场景保持可操作，并显示重试入口。过渡动画被取消时，导航状态回到最近的稳定场景。浏览器失去指针捕获时，拖拽状态立即结束。

## 验收标准

地图拖拽和缩放不会按动画帧触发整页重复渲染。缩放百分比随连续相机逐帧变化。父子图层在 80% 和 20% 作用域阈值保持相同实例。子域中的平移不会改变当前作用域。缩放临界点不会产生持续闪烁。折叠子空间无法响应指针事件。PixiJS 画布与地图宿主元素使用相同的 CSS 视口，10% 至 100% 缩放下的命中位置与图元位置一致。标签筛选节点和其他不可交互节点不会被 PixiJS 命中。场域保持定义颜色并在重叠处混色，单个场域内部不产生重复透明度。开发环境连续刷新后，每个地图宿主只保留一个 Canvas。连续进入和退出四层后，相机和面包屑保持一致。重复钻取后内存趋于稳定。更换未来地图渲染器时，知识 ID、关系和玩家进度保持兼容。
