# 知识卡片介绍规范

本文件是知识卡片介绍的写作真源。新增或重写卡片介绍以前，必须完整阅读本规范，并阅读“参考案例”链接指向的实际内容文件。内容条目仍以稳定概念 ID 关联知识图谱，标题和展示位置可以变化，概念 ID 与内容 ID 不随改名变化。

## 段落格式

卡片介绍按照读者理解知识的自然顺序组织。具体知识可以省略确实不适用的区段，但不能为了凑齐栏目写空泛段落。

1. **概念摘要**：用一句话说明研究对象和适用范围。摘要只负责定位，不承担完整解释。
2. **什么是该知识**：从日常经验、典型问题或学科背景进入，说明旧方法在哪里不够用，以及这一知识要解决什么问题。
3. **它是怎样形成的**：交代问题如何出现、关键方法如何发展，以及重要人物或时代分别贡献了什么。历史叙述服务于概念理解，不写孤立的人名和年份清单。
4. **核心概念**：每个重要概念单独成节。先给出具体情境，再说明推导过程、数学表达和应用含义。公式出现以前先说明问题，公式出现以后解释各个量代表什么。
5. **概念之间的联系**：说明各个核心概念为何能够组成同一套理论，必要时给出关键定理、因果关系或统一公式。
6. **图解与互动引导**：静态图负责建立整体认识，互动模块则让读者改变参数、观察结果并验证正文中的关系。图与互动都需要标题、说明和可访问文本。
7. **参考资料与复核信息**：列出支持正文的教材、学术机构资料或原始文献，并记录访问时间、许可和复核日期。

正文段落通常围绕一个主要意思展开。解释复杂概念时可以使用较长段落，但需要在对象、过程或论证发生变化时自然分段。避免连续堆叠过短句，也不要为了追求篇幅合并互不相干的内容。

结构化内容使用 `KnowledgeCardContent.sections` 保存。新增条目时可以从以下骨架开始：

```ts
import type { KnowledgeCardContent } from '../src/content/types'

export const exampleContent = {
  id: 'content:concept-id',
  conceptId: 'concept-id',
  summary: '说明研究对象和适用范围的简短摘要。',
  sections: [
    {
      id: 'concept-introduction',
      title: '什么是……',
      paragraphs: [
        '从具体语境进入，并完整解释问题。',
      ],
    },
  ],
  sources: [],
  frontierStatus: 'established',
  reviewedAt: '2026-07-29',
  reviewDue: '2027-07-29',
  widgetIds: [],
} satisfies KnowledgeCardContent
```

条目完成后需要加入 `src/content/index.ts` 的目录。来源类型、研究状态和日期格式以 `src/content/types.ts` 为准；互动组件 ID 需要先在 `src/widgets/registry.ts` 登记。

## 行文风格

卡片采用专业、耐心而自然的中文讲解。作者应当像熟悉该领域的人面对读者说明问题，让论述本身产生吸引力，不依赖口号或刻意制造悬念。

- 先铺设读者能够理解的语境，再进入抽象概念。标题优先使用“什么是……”“……是怎样形成的”“……怎样描述……”等自然问句。
- 根据真实的逻辑关系使用“然而、但是、因此、同时、则、不过、到了……”等连接词。连接词负责承接意思，不能按固定节奏机械添加。
- 需要比较不同方法或人物时，先完整说明一方，再自然过渡到另一方。主语和指代应当清楚，句子顺序符合中文由背景到问题、由现象到解释的阅读习惯。
- 允许长短句交替。一个句子只承担一个主要逻辑动作；一个段落只推进一个主要意思。
- 少用“不是……而是……”“真正重要的是……”“只需掌握N件事”等反转或清单式模板，也不要为追求对称而连续使用“把……”“前者……后者……”等刻意句式。
- 少写评价性的金句，多写具体对象、过程、条件和结果。专业术语首次出现时需要解释，不能假定读者已经理解。
- 历史事实、公式条件和应用结论必须能够追溯到来源。存在争议时明确说明分歧，不能为了叙事效果写成确定事实。
- 完稿后至少进行一次中文语序检查和一次朗读检查，清理翻译腔、模板化排比、重复结论与不自然的连接。

## 参考案例

[微积分正式卡片内容](../src/content/calculus.ts)是当前规范的直接参考案例，也是3D知识地图中“微积分”右侧卡片的实际内容来源。

新增或重写任何知识卡片介绍以前，作者和代理都必须先阅读该文件，重点观察以下内容：

- 开头如何从确定数量过渡到连续变化；
- 历史段落如何用问题发展串联人物与方法；
- 导数、积分和微积分基本定理如何依次解释；
- 公式出现前后的语境与说明；
- 正文、概念图、互动模块和来源记录之间的分工。

参考案例用于校准结构、解释密度和中文语感，不要求复制微积分的标题、段落数量或句式。每个知识点仍应根据自己的问题结构重新组织内容。
