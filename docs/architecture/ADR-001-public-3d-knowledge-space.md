# ADR-001：公共三维知识空间与可切换投影视角

日期：2026-07-27
状态：已采用

## 背景

现有数学地图使用二维空间表达前置关系、标签场域和多层钻取。项目将继续覆盖物理、化学和生物，并需要同时呈现学科内部结构与跨学科连接。单一二维坐标难以在保持各学科可读性的同时容纳跨领域邻近关系。

项目还计划在未来加入个人学习状态。公共知识结构、公共观察视角和个人认知状态需要保持独立，避免浏览行为改写共享知识事实。

## 决策

项目保留现有二维数学地图，并增加一套 Three.js 公共三维知识空间。两种视图共享稳定知识 ID，拥有各自的空间投影和渲染器。

三维空间使用一份规范节点与关系数据。节点保存公共三维位置、领域归属、层级和标签。关系保存前置、应用、类比、历史和共享模型等公开类型。数学、物理、化学、生物、跨域桥梁和全局视角通过透镜定义生成投影。

透镜只改变节点的显示位置、显著性、尺度、关系权重、场域强度和相机目标。透镜不复制节点，也不修改规范数据。切换透镜时，现有三维对象连续插值到目标投影。

第一阶段使用规则化、可复现的公共坐标和投影。个人掌握程度、兴趣和目标暂不改变公共坐标。后续个人化功能通过独立状态计算显著性与认知距离。

## 渲染边界

React 负责视图模式、透镜选择、详情面板和页面框架。PixiJS 继续负责二维地图。Three.js 负责三维卡片、关系线、柔和领域场、相机、命中检测和投影过渡。

三维卡片使用面向相机的 Sprite，并通过 CanvasTexture 生成文字纹理。节点命中使用 Raycaster。场域使用透明几何体和普通透明度混合。渲染器限制设备像素比并按宿主元素尺寸更新视口。

三维相机沿用二维地图的主要操作习惯。左键拖动平移，滚轮平滑缩放，Alt 加左键或右键拖动旋转。透镜切换由明确命名的界面控件触发。

## 选择理由

- Three.js 提供成熟的三维场景、相机、射线命中、纹理和资源释放接口。
- 保留 PixiJS 使现有二维连续钻取、标签场域和学习交互无需同时重写。
- 规范数据与投影分离后，同一节点可以在多个公共视角中保持身份一致。
- 规则化投影支持确定性测试，也能为后续物理模拟或嵌入式布局保留替换边界。

## 代价

- 应用需要维护 PixiJS 与 Three.js 两套渲染适配器。
- 三维文字需要纹理缓存、LOD 和可访问性替代入口。
- 三维位置表达公共设计选择，不能被描述为唯一客观坐标。
- 移动设备的 GPU、内存和输入能力差异需要独立性能预算。

## 被拒绝的方案

### 立即替换二维地图

该方案会同时重写成熟的二维钻取、命中和场域系统，迁移风险高，也会损失适合阅读学习路径的平面视图。

### 用 CSS 3D 或大量 DOM 元素构建空间

该方案便于排版，但大量节点、连线和连续投影会增加布局、合成和命中成本。

### 为每个学科维护一份独立节点副本

该方案会造成跨学科节点身份和内容漂移，关系修订也需要多处同步。

## 验收条件

1. 二维地图行为保持可用，用户可以明确切换二维和三维模式。
2. 三维空间至少覆盖数学、物理、化学和生物，并包含可见的跨学科桥梁。
3. 八个公共透镜投影同一组节点，切换过程连续，节点 ID 保持不变。
4. 三维节点可选择，空白处可关闭详情，拖动不触发点击。
5. 领域场保持柔和颜色，重叠处可混色，非聚焦领域仍保留空间上下文。
6. Three.js 资源在组件卸载时释放，画布尺寸与命中坐标一致。
