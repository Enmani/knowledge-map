# ADR-004：类型化子域关系与集中注册表

日期：2026-07-30
状态：已采用

## 背景

最初两个三维子域只声明 `prerequisites`，工厂把每条关系都生成为严格前置。这个约束适合数与运算、微积分的教学主干，却无法准确表达认知科学和神经科学中的建议背景、共享模型、类比或应用。把这些关系误写为严格前置会虚构学习顺序、增加严格前置深度，并可能制造没有知识意义的环。

子域列表原先直接写在 `App.tsx`。当子域从两个增长为几十个时，应用入口会同时承担内容目录、身份校验和界面状态，新增定义也容易遗漏搜索、详情或渲染接入。

## 决策

`ThreeSubspaceSourceNode` 使用显式 `relations` 列表。每条关系声明来源节点、关系种类、可选强度与标签；支持以下五种子域语义：

- `strict-prerequisite`：没有来源知识就无法稳妥理解目标知识。
- `recommended-prerequisite`：来源知识会提高理解效率，但不是必修顺序。
- `shared-model`：两项知识使用同一模型、表征或解释框架。
- `analogy`：两项知识可互相比较，但不主张机制相同。
- `application`：来源知识的方法或机制用于目标问题。

工厂把前两种映射为公共 `prerequisite` 关系及 `strict` / `recommended` 子类型，其余三种直接映射为公共关系类型。只有严格前置参与环检测；所有关系都必须解析到同一子域内的稳定源节点，不允许自指、重复关系或越界引用。

所有三维子域集中在 `subspaceRegistry.ts` 注册。注册表校验子域 ID、公共父节点和内部命名空间身份，`App.tsx` 只消费注册结果。一个公共父节点当前最多注册一个直接三维子域；更深层次继续由该子域自己的节点组织。

## 选择理由

- 关系语义与公共知识图一致，认知科学的竞争理论和跨模态联系不再被迫成为学习顺序。
- 严格 DAG 仍可计算知识深度，非严格关系可以形成双向或循环的语义网络。
- 注册表成为子域发现的单一真源，搜索、详情和渲染读取同一集合。
- 保持现有 `ThreeKnowledgeSubspace` 渲染契约，运行时不需要为不同学科增加分支。

## 代价与权衡

- 子域作者必须为每条关系选择类型，内容审核成本高于单一前置列表。
- 当前注册表是静态模块集合；当子域数量显著增加或需要按需下载时，应改为保留同一元数据契约的延迟加载清单。
- 注册表限制一个父节点对应一个直接子域。若未来需要并列子域入口，应先定义明确的选择交互，再放宽此约束。

## 验收条件

1. 注册表中的子域 ID、父节点和内部节点 ID 均唯一，且父节点存在于公共知识图。
2. 严格前置环在定义加载时被拒绝；由类比或共享模型组成的双向关系可以通过。
3. 已注册子域实际覆盖严格前置、建议前置、共享模型、类比和应用五种语义。
4. 数与运算、微积分、记忆、感觉与知觉、细胞与分子神经科学、认知神经科学均通过同一注册表进入搜索、详情和 Three.js 渲染。
5. 新增子域不需要修改 `App.tsx` 的子域数组。
